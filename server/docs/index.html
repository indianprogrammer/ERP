X3M ERP API

REST + MCP openapi.json

Authentication

Company (tenant) users only. Exchange credentials for a JWT, then send it on every request:

POST /api/auth/token
{ "username": "admin", "password": "…", "tenantSlug": "acme" }
→ { "token": "…", "refreshToken": "…", "expiresIn": "7d" }

Send Authorization: Bearer <token> on all other endpoints. Rotate via POST /api/auth/token/refresh. Web UI session cookies also work. Super-admin accounts cannot obtain tokens; every token is scoped to one company.

Conventions

  • Responses are JSON objects named after the resource: { customers: [...] }, { id }, errors as { error } with a proper status code.
  • Every query is tenant-scoped — a token can only ever touch its own company's data.
  • Permission denials return 403 with the missing permission, e.g. "No can_create access for sales".

MCP server (for AI agents)

Two transports, same tools. Tools call this API with your token, so company permissions apply.

1. Streamable HTTP — mount in any remote-capable MCP client

URL:         {origin}/api/mcp
Transport:   streamable HTTP (POST, stateless)
Authorization: Bearer <token from /api/auth/token>

2. stdio — run as a local subprocess (Claude Desktop / Claude Code)

ERP_API_URL is optional — defaults to http://<connect-host>:<PORT> from the project .env
{
  "mcpServers": {
    "x3m-erp": {
      "command": "node",
      "args": ["/path/to/ERP/mcp/stdio.js"],
      "env": {
        "ERP_TENANT": "acme",
        "ERP_USERNAME": "admin",
        "ERP_PASSWORD": "changeme123"
      }
    }
  }
}
